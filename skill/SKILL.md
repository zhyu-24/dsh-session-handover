# 派生新会话（交接）流程

把当前长会话的成果整理成一份可编辑的交接文档，然后由用户开一个全新的轻量会话继续工作。旧会话原样保留，不做任何修改、压缩或删除。

提示：若会话头部有「派生」按钮（handov 动态插件运行时），点按钮即可自动完成本流程；本 skill 是按钮不可用时的手动兜底，也是按钮流程的行为规范。

## 触发时机

- 用户明确表达「派生新会话 / 交接 / 开个新会话继续 / 轻装继续」等意图时，执行本流程。
- 长会话中，用户抱怨上下文太长、回答变慢时，可主动提议本流程：先一句话说明收益（旧会话保留、新会话干净上下文），征得同意后再执行。

## 流程

### 1. 盘点会话

通读当前会话，识别：

- 讨论过的每个议题或任务线索，及其状态（已完成 / 进行中 / 搁置 / 待办）；
- 哪些议题还有实际剩余工作，值得延续；哪些已闭环，不必延续；
- 关键决策、约定、文件位置、环境信息、踩过的坑。

### 2. 生成候选目标（预测）

基于盘点生成 3–5 个「新会话目标」候选：

- 每个候选 = 短标签（≤10 字）+ 一句话范围说明（涵盖什么、不含什么）；
- 只放值得延续的方向；会话只有单一主线时，候选可以是不同的侧重或下一步；
- 永远包含一个「综合继续」候选（说明：延续全部未完成议题）。

### 3. 询问用户（ask_user_question）

- 用 ask_user_question 弹出选择卡：multi_select 开启，选项 = 候选目标（label=短标签，description=一句话范围）。
- 提问文案中明确告诉用户：可以勾选一个或多个（多选 = 合并成一个目标）；都不满意可直接输入自定义目标（如「只要 SSH 部分，加上部署」）；也可勾选后在输入框写补充或修改要求。
- 若 ask_user_question 工具不可用：退化为普通文本，列出候选，请用户回复编号或自定义描述。

### 4. 写交接文档

按用户选择写交接文档到当前工作区根目录，文件名 HANDOVER-<目标slug>.md（综合继续 → HANDOVER-all.md；同名已存在则加日期后缀 HANDOVER-<slug>-<YYYY-MM-DD>.md）。文档第一行写：

> 父会话：<当前会话 id>（<当前会话标题>）

正文模板如下，只写有内容的节，宁缺毋滥：

```markdown
# 交接：<新会话目标一句话>

## 背景与现状
<按延续的议题分小节：目标 / 已完成 / 当前状态 / 下一步>

## 关键决策与约定
<列表>

## 相关文件与位置
<列表>

## 环境与常用命令
<代码块>

## 注意事项
<列表>

## 建议的第一步
<一句具体的起步动作>
```

写文档要求：

- 信息只来自本会话内容，不确定的标【待确认】，绝不编造；
- 按所选目标筛选：只保留与目标直接相关的议题，用户明确排除的内容绝不写；优先总结状态/决策/坑/下一步，避免按时间流水账；目标范围窄时文档相应更短；
- 文档是草稿：写完主动提示用户可先修改，再开新会话；
- 精炼优先，目标是让新会话用很少的上下文恢复工作状态；
- 全文只输出一份（不重复标题、不重复正文）。

### 5. 收尾提示

完成后告诉用户：

- 旧会话已原样保留，随时可回看；
- 点「新会话」（保持同一工作区），第一句说：按 HANDOVER-<slug>.md 继续（同时写明父会话 id，例如「父会话：session-xxx。按 HANDOVER-xxx.md 继续」）；
- 新会话将获得全新的干净上下文，只靠交接文档延续工作；
- 新会话需要回看父会话细节时：在输入框输入 @ 引用父会话，或用 parent_session_peek 工具（handov 动态插件安装时可用）按关键词查阅父会话。

## 禁止事项

- 不修改、不压缩、不删除旧会话的任何内容；
- 不调用压缩（compaction）相关工具；
- 交接文档不写与所选目标无关的议题细节（除非用户要求）。
